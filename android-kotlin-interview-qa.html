Kotlin Function

1. Override và Overload khác gì nhau?

Overload: cùng tên hàm nhưng khác số lượng tham số, kiểu tham số hoặc thứ tự tham số.

Override: class con viết lại implementation của hàm được khai báo từ class cha hoặc interface.

fun login(email: String, password: String) {}
fun login(phone: String) {}

open class Animal {
    open fun sound() {}
}

class Dog : Animal() {
    override fun sound() {
        println("Gau gau")
    }
}

2. OOP: đóng gói, đa hình, kế thừa, trừu tượng

Đóng gói

Đóng gói là che giấu dữ liệu bên trong class, không cho bên ngoài sửa trực tiếp nếu việc sửa đó cần kiểm soát điều kiện.

class User {
    private var age: Int = 0

    fun updateAge(newAge: Int) {
        if (newAge > 0) {
            age = newAge
        }
    }
}
Modifier Ý nghĩa
public Truy cập được từ mọi nơi. Đây là mặc định trong Kotlin.
private Chỉ truy cập trong class hoặc file đang khai báo.
protected Truy cập trong class đó và class con.
internal Truy cập trong cùng module.

Đa hình

Đa hình là cùng một hành động nhưng mỗi đối tượng có cách xử lý khác nhau.

interface Animal {
    fun sound()
}

class Dog : Animal {
    override fun sound() = println("Gau")
}

class Cat : Animal {
    override fun sound() = println("Meo")
}

Lưu ý khi phỏng vấn: ví dụ “Dog có màu lông khác nhau” là khác giá trị thuộc tính, chưa phải đa hình. Đa hình nên nói về cùng method/interface nhưng hành vi khác nhau.

Kế thừa

Class con nhận lại thuộc tính hoặc hành vi từ class cha.

open class BaseAnimal {
    fun eat() {}
}

class Husky : BaseAnimal()

Trừu tượng

Trừu tượng là chỉ lộ ra hành động cần làm, còn xử lý cụ thể được giấu bên trong implementation.

interface Payment {
    fun transfer(amount: Long)
}

class MomoPayment : Payment {
    override fun transfer(amount: Long) {
        // Xử lý chuyển tiền qua Momo
    }
}
Kotlin Model

3. Data class và class khác nhau như thế nào?

data class dùng để biểu diễn dữ liệu. Kotlin tự sinh equals(), hashCode(), toString(), copy() và componentN().

class thường dùng khi object có hành vi, trạng thái phức tạp hoặc lifecycle riêng.

data class UserDto(
    val id: Int,
    val name: String
)

class UserManager {
    fun syncUser() {}
}

Dùng data class cho model API, request/response, UI state. Dùng class thường cho manager, controller, custom view, repository.

Android XML UI

4. Các loại layout trong XML

Layout Cách dùng
ConstraintLayout Linh hoạt, phù hợp UI phức tạp, ràng buộc view với parent hoặc view khác. Thường tối ưu hơn layout lồng nhau quá nhiều.
LinearLayout Sắp xếp view theo chiều dọc hoặc ngang bằng orientation.
FrameLayout Các view con xếp chồng lên nhau. Hay dùng làm container cho Fragment.
RelativeLayout Sắp xếp dựa trên vị trí tương đối giữa các view. Hiện ít được ưu tiên hơn ConstraintLayout.
ScrollView Dùng khi nội dung dài cần cuộn, thường chỉ chứa một child trực tiếp.
CoordinatorLayout Dùng với behavior như AppBar, CollapsingToolbar, Snackbar.
Fragment Transaction

5. So sánh replace và add Fragment

API Hành vi Khi dùng
add() Thêm Fragment mới vào container, Fragment cũ vẫn còn nếu không hide() hoặc remove. Dùng khi muốn giữ state Fragment cũ, ví dụ tab.
replace() Remove Fragment hiện tại trong container rồi add Fragment mới. Dùng khi chuyển màn và không cần giữ view cũ. 
supportFragmentManager.beginTransaction()
    .replace(R.id.container, DetailFragment())
    .addToBackStack(null)
    .commit()

Nếu cần bấm Back quay lại Fragment trước, thêm addToBackStack().

Lifecycle Android OS

7. Đang dùng app có cuộc gọi đến thì lifecycle chạy như thế nào?

Nếu cuộc gọi che app hoàn toàn, Activity thường đi qua onPause() rồi onStop(). Khi cuộc gọi kết thúc và quay lại app, Activity chạy onRestart(), onStart(), onResume().

App đang foreground
→ onPause()
→ onStop() nếu bị che hoàn toàn

Cuộc gọi kết thúc, quay lại app
→ onRestart()
→ onStart()
→ onResume()

Nếu app chỉ bị che một phần, có thể chỉ chạy onPause() rồi onResume().

Network Retrofit

8. Retrofit và các phương thức GET, POST, PUT, DELETE

interface ApiService {
    @GET("users")
    suspend fun getUsers(): List<User>

    @POST("users")
    suspend fun createUser(@Body user: User): User

    @PUT("users/{id}")
    suspend fun updateUser(
        @Path("id") id: Int,
        @Body user: User
    ): User

    @DELETE("users/{id}")
    suspend fun deleteUser(@Path("id") id: Int)
}
  • GET: lấy dữ liệu.
  • POST: tạo mới dữ liệu.
  • PUT: cập nhật dữ liệu.
  • DELETE: xóa dữ liệu.
RecyclerView Adapter DiffUtil

9. RecyclerView

Thành phần chính

Thành phần Vai trò
Adapter Quản lý data, tạo ViewHolder và bind data vào item view.
ViewHolder Giữ reference đến view con và bind dữ liệu cho từng item.
LayoutManager Quyết định list hiển thị dọc, ngang, grid hoặc staggered grid.
ItemDecoration Thêm spacing, divider hoặc decoration cho item.

Các loại notify thường dùng

  • notifyDataSetChanged(): báo toàn bộ list thay đổi, ít tối ưu.
  • notifyItemChanged(index): update một item.
  • notifyItemInserted(index): thêm một item.
  • notifyItemRemoved(index): xóa một item.
  • notifyItemRangeChanged(start, count): update nhiều item liên tiếp.

Case API load chậm 3 giây: ban đầu show loading hoặc empty state. Khi API trả data, update list trong adapter rồi notify. Cách tốt hơn là dùng ListAdapter + DiffUtil và gọi submitList(newList).

viewModel.users.observe(viewLifecycleOwner) { users ->
    adapter.submitList(users)
}
Coroutine Flow Dispatcher

10. Coroutine

Khái niệm Cách hiểu
launch Chạy coroutine không trả kết quả trực tiếp.
async/await Chạy coroutine có kết quả trả về, lấy kết quả bằng await().
withContext Chuyển context/dispatcher, thường dùng để chạy IO hoặc CPU task.
Flow Stream bất đồng bộ, có thể emit nhiều giá trị theo thời gian. 
viewModelScope.launch {
    val users = withContext(Dispatchers.IO) {
        api.getUsers()
    }
    _uiState.value = UiState.Success(users)
}

Dispatcher

  • Dispatchers.Main: update UI.
  • Dispatchers.IO: call API, database, file.
  • Dispatchers.Default: xử lý CPU nặng.
  • Dispatchers.Unconfined: ít dùng trong app thực tế.

Clean Code Maintainability

12. Clean Code

  • Đặt tên biến, hàm, class rõ nghĩa.
  • Mỗi function nên làm một nhiệm vụ chính.
  • Tránh duplicate code.
  • Không hardcode nếu giá trị có thể thay đổi hoặc tái sử dụng.
  • Tách logic khỏi UI.
  • Class nên có trách nhiệm rõ ràng.
  • Code dễ đọc quan trọng hơn code ngắn nhưng khó hiểu.
  • Follow convention Kotlin/Android của project.
Firebase FCM Crashlytics

16. Firebase

Firebase Cloud Messaging

Loại message Đặc điểm
Notification message Android system/Firebase có thể tự hiển thị notification khi app ở background.
Data message App tự xử lý payload, phù hợp khi cần custom logic.
  • Foreground: thường nhận qua onMessageReceived().
  • Background: notification message thường do system hiển thị; data message cần xử lý cẩn thận vì có giới hạn background.

Dịch vụ Firebase hay gặp

  • Firestore hoặc Realtime Database: lưu data cloud/realtime.
  • Firebase Storage: lưu file, ảnh, video.
  • Crashlytics: theo dõi crash production.
  • Analytics: tracking event, screen, click.
  • Authentication: login Google, email, phone.
  • App Distribution: upload APK/AAB cho tester tải về test.
Debug Crashlytics Sentry

18. Từng debug crash bằng Sentry, Crashlytics, Logcat

Cách trả lời phỏng vấn: “Khi có crash, em xem stacktrace trên Crashlytics/Sentry trước, kiểm tra version app, device, OS, breadcrumbs và steps nếu có. Sau đó reproduce local, xem Logcat, đặt breakpoint hoặc thêm log để xác định nguyên nhân rồi fix và verify lại.”

  • Logcat: xem log runtime khi chạy local.
  • Crashlytics: xem crash production, stacktrace, device, OS version.
  • Sentry: tracking error, breadcrumb, context, user flow.
Architecture MVVM

19. MVVM

View ViewModel Repository/DataSource API/Database

View gửi action như getProfile() cho ViewModel. ViewModel gọi Repository/DataSource để lấy dữ liệu. Khi có kết quả, ViewModel update state. View observe state và render UI.

View → ViewModel → Repository/DataSource → API/Database
View ← State/LiveData/Flow ← ViewModel

View không nên xử lý business logic. ViewModel giữ UI state và logic liên quan đến màn hình.

Storage Android

20. Internal Storage và External Storage

Internal Storage External Storage
Bộ nhớ riêng của app, app khác không truy cập được trực tiếp. Vùng lưu trữ bên ngoài hoặc vùng người dùng có thể thấy, tùy loại file và API.
Khi uninstall app, data thường bị xóa. Phù hợp lưu ảnh, file download, document hoặc file cần chia sẻ.
Dùng cho config, cache nội bộ, file private. Một số trường hợp cần permission hoặc dùng Storage Access Framework/MediaStore.
File HTML này được hệ thống lại từ bộ câu hỏi Android/Kotlin và có thể mở trực tiếp bằng trình duyệt.
