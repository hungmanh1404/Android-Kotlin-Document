1. Kotlin nền

1.1 Cú pháp & khái niệm cốt lõi

val bất biến, var có thể đổi. Điều khiển: if là biểu thức, when, vòng lặp for/while. Hàm có thể rút gọn một dòng. Null: ?, ?:, !! (tránh lạm dụng). Smart cast với is.

Chủ đềGhi nhớ nhanh
Biếnval / var
CollectionlistOf, mutableListOf, filter/map
ClassConstructor rút gọn, property, data class cho DTO
Lambda / HOFHàm làm tham số; filter, map là ví dụ HOF

1.2 “Cheat sheet” String / Number / List

String: trim, split, substring, replace, isBlank. Number: toInt(), coerceIn, random(). List: filter/map/sorted, mutable add/remove.

1.3 Generic (tổng quát hóa kiểu)

Viết fun <T> … khi logic giống nhau cho nhiều kiểu (ví dụ firstElement(list: List<T>)).

1.4 Idioms Kotlin (tóm tắt)

  • data class cho model; tham số mặc định thay overload.
  • by lazy khởi tạo lười; use đóng resource.
  • object singleton; companion object như static.
  • inline + reified khi cần kiểu generic lúc runtime (ví dụ Gson).

Chi tiết đầy đủ: Kotlin_Basic_Syntax_Summary.md, kotlin_method.md, Generic_Function.md, Kotlin_Idioms_Analysis.md.

Intent: Explicit vs Implicit

  • Explicit: chỉ rõ class — thường trong cùng app.
  • Implicit: chỉ action + data/type — hệ thống chọn app xử lý (trình duyệt, gọi điện, SMS…).

Thành phần Intent: component name, action, data, category, extras, flags.

Application là singleton; mỗi Activity/Fragment là instance mới; ViewModel là instance theo scope; Repository thường singleton để dùng chung.

4. Thread & Coroutine (bất đồng bộ)

4.1 Bức tranh từ User → CPU

USER ACTION → Lifecycle owner (Activity / Fragment / ViewModel) → Scope (lifecycleScope / viewModelScope) → Coroutine (launch / async) → suspend (delay, Retrofit, Room) — không = thread → Dispatcher (Main / IO / Default) → Thread (OS) → CPU

4.2 Phân biệt Dispatcher (từ tài liệu Thread)

DispatcherBản chấtVí dụ việc
MainMột luồng UI, gắn LooperVẽ UI, click, lifecycle
DefaultPool CPU, ~ số coreSort, DiffUtil, parse JSON lớn
IOPool lớn cho chờ/blockingNetwork, file, DB

4.3 viewModelScope vs lifecycleScope

Logic / data / API → viewModelScope
Render / collect / animation gắn UI → lifecycleScope (hoặc viewLifecycleOwner trong Fragment)
Phải biết scope gắn với cái gì và hủy khi nào.

4.4 withContext vs launch lồng nhau

  • withContext: cùng một coroutine, đổi “phòng” (dispatcher) — tuần tự, kiểm soát thứ tự.
  • launch bên trong: tạo coroutine mới — có thể chạy song song, dễ mất thứ tự nếu không chờ.

Pattern an toàn: lấy dữ liệu trên IO bằng withContext, rồi cập nhật UI trên Main trong cùng launch gốc.

viewModelScope.launch { val user = withContext(Dispatchers.IO) { api.getUser() } showUser(user) // chắc chắn sau khi IO xong }

4.5 Chuỗi khái niệm (phỏng vấn)

Coroutine không tồn tại để “nhanh hơn thread” mà để dùng thread thông minh hơn: CPU → Thread → Coroutine → Dispatcher → Scope → Lifecycle.

Xoay màn hình (configuration change)

Rotation = đổi cấu hình → UI bị destroy và tạo lại; process vẫn sống. Dữ liệu UI nên giữ ở ViewModel / saved state, không chỉ biến trong Activity.

Nguồn: Readme.md, Thread_Concept_Android.md, Android_Engineers_Questions.md.

5. Lưu trữ & kiến trúc dữ liệu

5.1 SharedPreferences vs Room

Tiêu chíSharedPreferencesRoom
Mục đíchKey–value đơn giảnDữ liệu có cấu trúc, quan hệ
Kiểu dữ liệuPrimitive + StringEntity, quan hệ, truy vấn
NềnXML (load cả file)SQLite + DAO
Quy môNhỏ (<~1MB)Lớn, có index
Flow/LiveDataKhông nativeHỗ trợ

Cảnh báo bộ nhớ: đừng nhét JSON list khổng lồ vào Prefs (cả file vào RAM). Room vẫn có thể OOM nếu SELECT * không giới hạn — dùng LIMIT, Paging, Flow.

5.2 UDF (Unidirectional Data Flow)

UI gửi Event → ViewModel xử lý → cập nhật State → UI observe / collect → render lại Compose: stateless UI + collectAsState XML: LiveData/Flow observe

8. Ôn phỏng vấn (rút gọn từ folder)

  • Override vs Overload: ghi đè lớp cha vs cùng tên khác tham số.
  • super: gọi logic lớp cha trong override.
  • LiveData encapsulation: MutableLiveData private, expose LiveData read-only.
  • Class vs data class: hành vi vs holder dữ liệu (equals/copy/toString).
  • Access modifiers: public (mặc định), internal, protected, private.
  • Class vs object: nhiều instance vs singleton object.
  • Đa kế thừa: không đa class; nhiều interface được.
  • ListView vs RecyclerView: tái sử dụng view, hiệu năng, layout linh hoạt.
  • Chọn nhiều item: MutableSet index/id.
  • Parse số an toàn: toIntOrNull().
  • lateinit vs lazy: var khởi tạo sau vs val tính lần đầu.
  • Layout: Frame (chồng), Relative (tương đối), Constraint (linh hoạt, hiệu năng tốt hơn Relative).
  • HOF: tham số/return là function; ví dụ filter, map.
  • Enum cho input type: tránh “string tự do”, type-safe.

Chi tiết: Android_InterView_Questions.md, Android_Engineers_Questions.md. Link tham khảo trong file gốc.
